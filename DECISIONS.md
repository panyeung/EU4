## 2026-11-10 - The Unity Pipeline bridge is the supported agent control path

- Decision: Treat `com.unity.pipeline` 0.8.0-exp.1 plus the `unity` CLI as the project's supported way for an agent to drive the already-open Editor, and keep the project-local verification skills that depend on it. No package, provider, or plan was added or changed by this decision; the package was already in `Packages/manifest.json`.
- Capability: `unity pipeline list` reports the instance and port (Editor server 7800-7849; this checkout answered on 7801). Verified working against PID 126040: `editor_status`, `open_scene`, `editor_play`, `editor_stop`, `editor_focus`, `recompile`, `recompile_status`, `console`, `console_status`, `run_script`, `capture_game_view`.
- Why it matters: agent acceptance no longer needs GUI automation for the common path, `run_script` compiles arbitrary C# against the project assemblies outside `Assets/` (no domain reload), and that makes it possible to exercise the real gameplay code with generated inputs instead of a hand model. `-batchmode` remains forbidden while an Editor holds this folder.
- Constraints found by use: `capture_game_view --save_path` always resolves under `Assets/` (absolute paths are remapped, `..` is rejected) and Unity then warns `Files generated by test without cleanup`, so captures are written to `Assets/Logs/verify/_scratch/` and deleted with `Assets/Logs` plus `Assets/Logs.meta`. Play Mode stalls while the Editor is unfocused (`VerifyUi.State` freezes its frame counter and captures return stale frames); `unity command editor_focus` restarts the advance. Windows PowerShell 5.1 strips the quotes out of `--args '["..."]'`, so scripts that need an argument build the JSON in-process.
- Verification boundary: Lead-run. Play Mode was entered on `FoundationScene`, the title → `选择剧本` → `固定三代剧本（SC-013）` path completed, and the campaign HUD read `1560 年 4 月 1 日` with 0 console errors; evidence is `Logs/verify/20261110-2332-title-new-game.md`. This is agent evidence under the standing Play Mode authorization, not user acceptance.

## 2026-11-03 - SC-017 builds a small custom read-only family graph

Reuse existing `SuccessionState`/`SuccessionWorld` membership and life data plus typed `KinshipGraph` facts; add no package, code, asset, or dependency from the reviewed repositories.
- Prior art: Scout reviewed at most three Unity-relevant candidates. - Layout: Derive generations from parent/child and adoption edges; align spouses and siblings to the same generation. Sort persons/edges by stable IDs and type, place cards in deterministic generation rows, and put unconnected kin and household members in separate labelled bands below all kin. No SC-013 name, ID, count, or preset generation is used.

Retainers, disciples, and guests never receive kinship lines. The panel is strictly read-only and rebuilds only transient clones; opening, closing, scrolling, or refreshing does not mutate succession, family, kinship, save, or event state.
- Scene integration: Extend the existing `AddSC013FamilyRosterPanel` transactional updater to build the scroll/content/edge/node/template hierarchy in one Undo group with validate-before-save and rollback without scene reload. It recognises and replaces only the exact previous row hierarchy; any other partial roster object is refused. `FoundationSceneValidator` checks the new bindings and delegates full hierarchy validation to the updater validator.
- Verification boundary: After the final spouse-routing correction, Unity's bundled Roslyn compiled the eight source assemblies with 0 errors and the pure graph/layout harness passed 86/86 checks (77 existing checks plus 9 routing checks).
