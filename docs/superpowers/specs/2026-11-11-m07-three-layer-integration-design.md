# M07 三层玩法整合设计稿

**节点：** M07
**状态：** M07 设计与完整数值方案已获用户批准（2026-11-11），用户随后批准开始代码实施。代码、测试源与文本文档已写入当前工作树；2026-11-12 运行验证轮在既有 Unity Editor 取得编译成功、全量 EditMode `1710/1710`、`FoundationSceneValidator` PASS（Errors 0）与 M05/M06 手动/委派实况路线，最终用户里程碑验收仍待办。M06 自动检定、四类可用结果、手动映射、准备选项、警戒成本、名望/关系/隐蔽度变化、死亡概率和初始值见实施计划。
**依据：** `GDD_v4.0.md` §2.1、§8、§13 M07、§19.8；已实现的 M02–M06、M04A 人物记忆与 M04B 动态家族系统。

## 意图

让家族经营、人物日常活动和战术行动成为同一场持续战役：玩家能在管理中安排人物、选择亲自执行或自动委派任务；任务结果改变相同的家族人物与世界状态；人物经历和家族编年分别归属于正确的人；存档、读档及继承后仍能继续。

用户已确认：手动和自动操作方式的奖励相同，只改变操作方式；同一任务结局不能设置模式专属奖励。此设计据此要求两种方式经过同一个结果及后果结算路径。

## 目标

- 把战术队员和家族人物映射到同一稳定人物 ID；不复制一套战术人物状态。
- 在任务简报中提供亲自执行/自动委派选择；所有任务都可选择两种方式，不设强制手动任务。
- 自动委派按 GDD §8.3，依据出发时的队伍、能力、情报、准备、资源、难度和可重现随机因素确定结果；手动沿用相应任务既有的操作与结局判定。M07 不新增由操作模式本身触发的结果修正或专属奖励。两种方式使用同一结果枚举与结算入口；相同任务结局必须产生相同奖励、人物后果、经历和编年内容。具体映射见实现计划。
- 任务结果能更新任务队员的伤势/死亡状态、任务奖励、家族名望、独立的隐蔽度、逐雇主信用及明确列出的世界关系，且每个结果只提交一次。
- 让个人行动安排、任务占用和月度推进对同一人物时间预算保持一致；任务出发后不允许重复分配或不合法行动。
- 让任务经历记入每名实际参与者的个人经历，并在家族编年中仅记一条任务结果；人物继承后按原人物 ID 保留个人经历归属。
- 从管理开始完成个人活动、一次任务、结算、存档/读档和至少一次家主交接，且恢复后人物与世界状态一致。

## 非目标

- 不替换已实现的回合制潜入规则、世界地图或人物 UI。
- 不增加新的战斗类型、战役地图、通用任务编辑器、多人系统、付费服务、外部依赖或第三方商业游戏内容。
- 不在 M07 同时扩展完整外交、战争模拟或 M08 的大规模正式内容。
- 不改变用户已确认的手动/自动同结果奖励规则。

## 设计路径

1. **单一结果结算（本稿选择）**：手动任务与自动委派共用任务定义、结果类型和一次性结算。手动沿用任务已有操作；自动按 GDD §8.3 规则解析。M07 不添加模式专属结果修正或奖励，适合当前 M06 战术状态和任务结算边界。
2. **手动和自动各自结算**：手动沿用战术执行，自动另走独立月度/属性流程。实现看似局部，但容易产生奖励、伤病、经历和编年差异，违反同结果同奖励并扩大验证矩阵。
3. **独立战术人物和战役存档**：战术场景复制队员与结局，再在退出时同步回家族。它会造成身份冲突与重复提交风险，与 M07 的共用人物身份及存档要求相反。

**已批准规则：**所有任务委托都提供手动与自动两种操作，不设置仅手动任务。手动沿用任务已有的操作与结局判定；自动根据出发队伍、能力、情报、准备、资源、难度和可重现随机输入结算。两种操作读取同一任务简报和人物状态，并将结果交给同一结算入口。M07 不新增模式专属结果修正；同一任务结局不得因操作方式改变奖励、人物后果、经历或编年。

## 核心流程

1. **管理与安排**：玩家查看家族人物、个人活动计划及可用任务。所有活动检查人员是否存活、是否受伤、位置、已有时间占用和任务资格。
2. **任务简报**：显示目标、参与者、花费与行动占用、成功/代价/失败风险、已知敌情及可能人物后果；玩家可返回调整队伍，或选亲自执行/自动委派。
3. **执行**：亲自模式进入当前战术任务；委派模式以相同人员和出发状态调用自动解算。二者均不提前改变奖励或后果，任务期间禁止对队员进行冲突安排。
4. **一次性结算**：将任务标识、结果、日期、参与者及实际变化送入一个应用层结算入口。入口校验并原子提交人物状态、资源/名望/关系变化、个人经历及唯一家族编年条目；无效或重复提交不得造成部分写入。
5. **恢复家族循环**：结果回到管理 UI，显示前后值及个人/家族影响。人物可继续合法活动，月份按现有顺序结算；任务完成或资源不足等 GDD 暂停条件按既有规则暂停自动推进。
6. **保存与继承**：只允许在稳定管理/任务结果节点保存；加载恢复人员、任务完成状态、经历、编年、资源和结算幂等性。家主更替不转移个人经历，家族编年保持在同一条家史中。

## 规则与数据边界

- 人物身份与当前角色统一由现有家族/人物数据拥有；任务记录只引用稳定人物 ID。
- 任务活动占用需复用现有 `DailyActionState` / 任务执行状态；不得新增并行的玩家可见时间预算。
- 自动解算提议按任务启动时冻结的队伍、能力、情报、准备、资源、难度与一个可保存/重现的随机流输入。读档后不可再次结算已提交任务。
- 所有任务共用 GDD §8.3 的五种结果，使用同一套结果数据和结算处理：

| 结果 | 目标状态 | 可能的共同后果 |
| --- | --- | --- |
| 完全成功 | 主要目标完成 | 完成奖励；任务定义的名望、信用、隐蔽度和世界关系变化；按任务定义产生经历。 |
| 成功但有代价 | 主要目标完成 | 完成奖励加明确代价；可能造成队员受伤或资源损失。 |
| 部分成功 | 仅部分目标完成 | 仅发放已完成目标对应奖励；记录未完成目标及对应关系/政治变化。 |
| 失败并安全撤离 | 目标未完成，队员撤出 | 不发完成奖励；按任务定义结算花费、关系变化与可恢复伤势，不可直接死亡。 |
| 严重失败 | 目标未完成且行动崩溃 | 任务定义可造成伤势或死亡；死者必须在简报中说明可能性，不能由未告知的随机事件直接杀死关键继承人。 |

  五种结果是 M07 共用结果类型；单项任务只生成其规则支持的结果。M06 当前只有一个密报目标，因此首切片不生成“部分成功”。旧任务阶段必须逐项映射到共用结果；不适用或缺失映射不得静默当作部分成功或零效果。
  同一任务结果记录包括确切受影响人物和效果；相同任务、相同结果记录必须写入相同奖励、人物后果、经历和编年内容。若检定结果不同，则由任务结局本身解释差异，不能按操作模式调整结算。
- **已批准的伤病/死亡规则：**人物状态为存活且无伤、存活且受伤、死亡。受伤者在一次后续月度结算前不能参与体力/潜入任务，但可进行不冲突的管理活动；月度结算后伤势自动恢复，不改变基础能力。死亡是永久状态，保留 ID、亲属关系、经历和编年，退出所有任命/行动并从继承候选中移除。M07 之前的实现不支持死亡家主继续作为有效在任家主；M07 已实现明确的死亡继承转换：成年继承人接位、未成年继承人进入摄政、没有合法候选人则进入可保存的危机决策状态。危机解决前暂停依赖存活家主的操作。只有严重失败可触发死亡，且简报必须明确告知可能死亡的队员。任务的每名队员后果来自任务结果数据，而非手动/自动模式。
- **名望、信用和世界关系：**按 GDD 分离家族名望与隐蔽度；雇主信用按雇主 ID 保存；不把名望当成隐蔽度的反向值。每个任务结果明确列出它影响的雇主/势力和数值前后值；不允许“世界变化”成为未定义的泛化字段。
- 结果事务记录每名队员伤病/死亡前后值、每类资源和名望/隐蔽度/信用/势力关系的实际增减、人物经历条目及唯一家族编年。UI 对发生的变化展示 before/after。
- 上述伤病时长、严重失败死亡限制及手动/自动选择规则已由用户批准。实现计划须规定各任务的可用结果、资源与关系变化，并确保简报显示对应风险和数值前后值。
- **已批准的 M06 数值方案：**难度固定 50；队伍忍术取两名出发成员的平均并向下取整，冻结情报按 1 点换 1 分且最高 +10，准备加值为 0 或 +10，使用可重现 d100（1–100），检定分数为 `floor((忍术A + 忍术B) / 2) + clamp(情报, 0, 10) + 准备加值 + d100 - 50`。分数 `>=90` 为完全成功，`65–89` 为成功但有代价，`15–64` 为失败并安全撤离，`<15` 为严重失败；M06 不产生部分成功。手动模式将无警戒撤离映射为完全成功、警戒后撤离映射为成功但有代价并多付 1 物资、主动撤退映射为失败并安全撤离、被抓获映射为严重失败。成功奖励沿用资金 +4、情报 +6；每个任务支付基础 2 物资，侦察准备另付 1 物资，成功但有代价另付 1 物资，所有费用只在共享终局结算扣除。五种结果的名望变化为 `+3/+2/+1/-1/-3`，适用关系变化为 `+5/+2/+1/-3/-5`，隐蔽度变化为 `+3/+1/0/-2/-5`。初始名望 0、隐蔽度 50，未记录的雇主信用/势力关系默认 0。严重失败时，简报逐名列出的每名队员独立进行 10% 死亡检定，幸存者受伤。范围分别为名望/隐蔽度 `0..100`、关系 `-100..100`，越界时截断。
- 失败、撤退和结果提交失败是不同状态。提交失败应保留可重试或可恢复的原状态，不能写入部分资源、人物或历史变化。
- 存档模式迁移遵循现有 `SaveDataMigrator` 与 `SaveDataValidator`；若新增字段则提升 schema 并覆盖当前受支持旧版本，原始存档无效时不得覆盖。

## 验收体验

- 在同一场战役中安排个人行动并执行一项可手动/可委派任务；玩家能够看到任务占用与冲突理由。
- 手动完成至少一个成功结局，并通过自动委派完成有相同冻结输入和相同结果的测试用例；断言资源奖励、人物后果、个人经历与家族编年完全一致。Play Mode 验证两个操作入口可用，模式本身不授予专属奖励。
- 在 M05/M06 支持的结果中合计覆盖完全成功、成功但有代价、部分成功、失败并安全撤离、严重失败五类；确认简报、统一结算、实际代价与重复提交保护。未被单项任务支持的结果必须明确不可达，不能静默映射。
- 将一名队员的任务结果写回原家族人物；检查人物身份、伤病/存活状态、个人经历、家族编年及世界变化。
- 在终局管理界面保存、退出并读档；完成至少一次家主交接后，确认任务结果与人物经历仍归属于原参与者、家族历史未重复。
- 用户可以解释手动与自动差异、简报中的风险和每项结果变化；若差异看似是模式奖励或任务强制要求手动，验收失败。

## 已批准规则与实现计划范围

2026-11-11，用户批准了以下规则：

1. 每项任务均可手动执行或自动委派，不设强制手动任务。
2. 自动结算使用出发队伍、能力、情报、准备、资源、难度和可重现随机输入。
3. 手动与自动共用完全成功、成功但有代价、部分成功、失败并安全撤离、严重失败五种结果及同一结算入口。同一结局具有相同的奖励、人物、经历和编年后果。
4. 受伤者在一次后续月度结算前不能参与体力/潜入任务；月结后自动恢复。只有严重失败且简报已告知死亡风险时才可死亡。
5. 家族名望与隐蔽度独立保存；雇主信用与势力关系由稳定 ID 键控。

2026-11-11，用户批准五种结果的名望变化 `+3/+2/+1/-1/-3`、适用雇主信用/势力关系变化 `+5/+2/+1/-3/-5`、名望/隐蔽度范围 `0..100` 及关系范围 `-100..100`。超出边界时截断状态值，终局记录保存实际前后值。

按用户授权，M06 准备可选：“不准备”冻结 `PreparationBonus=0`、额外成本 0；选择“侦察路线”则冻结 `PreparationBonus=10`、额外成本 1 物资。自动解析将加值加入准备评分，手动简报在已知起始位置/朝向上补出第二个巡逻航点 `(7,0)`，揭示 `(7,1) → (7,0)` 环线。两种模式冻结相同选择与成本，但按操作方式呈现效用；模式不进入奖励/后果配置。固定开局为 12 物资、0 情报，因此侦察路线开局可用。选择和启动时不扣物资；无准备时启动需至少 2 物资，选择侦察路线时需至少 3 物资。对应的 2 或 3 物资只在共同终局结算时扣除。取消未启动的选择不改变资源。规则复用现有物资与 authored patrol route，不增加新资源、依赖或战术指令。

M06 现有手动终局只有合法带密报撤离 `Succeeded`、主动撤退 `Withdrawn`、被抓获 `Failed`；M07 之前的实现不按守卫警戒区分结局，也没有部分目标状态。用户已批准 M07 增加“警戒后撤离→成功但有代价”分支并额外消耗 1 物资。该分支已由 `TacticalMissionResolutionRules.TryMapManual` 接入 M07 共享映射与结算；2026-11-12 的 Play Mode 覆盖委派失败、手动撤退、手动/委派严重失败，以及手动带密报撤离（警戒后撤离 → 成功但有代价）与无警戒带密报撤离（完全成功）；先前手动补充尝试本身被抓获，未到达警戒后撤离分支。

日常休息、训练、工作和旅行继续使用 `DailyActionState`，不作为任务委托，也不增加手动/自动任务模式。已批准的检定公式、任务数值、存档迁移、与 `ShadowEscortCommission`/`TacticalMissionState` 的映射及连续试玩路径已写入实施计划。代码实施已完成；超出上述范围的玩法扩张需另行审阅。
