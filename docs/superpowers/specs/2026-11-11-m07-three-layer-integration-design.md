# M07 三层玩法整合设计稿

**节点：** M07
**状态：** 待用户审阅
**依据：** `GDD_v4.0.md` §2.1、§8、§13 M07、§19.8；已实现的 M02–M06、M04A 人物记忆与 M04B 动态家族系统。

## 意图

让家族经营、人物日常活动和战术行动成为同一场持续战役：玩家能在管理中安排人物、选择亲自执行或自动委派任务；任务结果改变相同的家族人物与世界状态；人物经历和家族编年分别归属于正确的人；存档、读档及继承后仍能继续。

用户已确认：手动和自动操作方式的奖励相同，只改变操作方式；同一任务结局不能设置模式专属奖励。此设计据此要求两种方式经过同一个结果及后果结算路径。

## 目标

- 把战术队员和家族人物映射到同一稳定人物 ID；不复制一套战术人物状态。
- 在任务简报中提供亲自执行/自动委派选择。负责人提议所有任务均可选择两种方式、不设强制手动任务；此项尚待用户确认。
- 自动委派提议按 GDD §8.3，依据出发时的队伍、能力、情报、准备、资源、难度和随机因素确定结果；手动玩法由玩家输入影响结果。两种方式使用同一结果枚举及结算效果。相同任务、相同结果与相同受影响人物时，资源奖励、人物后果、经历和编年内容完全相同。具体检定方案尚待用户批准。
- 任务结果能更新任务队员的伤势/死亡状态、任务奖励、家族名望、独立的隐蔽度、逐雇主信用及明确列出的世界关系，且每个结果只提交一次。
- 让个人行动安排、任务占用和月度推进对同一人物时间预算保持一致；任务出发后不允许重复分配或不合法行动。
- 让任务经历记入每名实际参与者的个人经历，并在家族编年中仅记一条任务结果；人物继承后按原人物 ID 保留个人经历归属。
- 从管理开始完成个人活动、一次任务、结算、存档/读档和至少一次家主交接，且恢复后人物与世界状态一致。

## 非目标

- 不替换已实现的回合制潜入规则、世界地图或人物 UI。
- 不增加新的战斗类型、战役地图、通用任务编辑器、多人系统、付费服务、外部依赖或第三方商业游戏内容。
- 不在 M07 同时扩展完整外交、战争模拟或 M08 的大规模正式内容。
- 不改变用户已确认的手动/自动同结果奖励规则。

## 设计路径

1. **单一结果结算（本稿选择）**：手动任务与自动委派共用任务定义、结果类型和一次性结算；入口只决定输入方式，任务成败可以不同。优点是模式差异清楚且存档、人物后果一致，适合当前已存在的 M06 结算路径。
2. **手动和自动各自结算**：手动沿用战术执行，自动另走独立月度/属性流程。实现看似局部，但容易产生奖励、伤病、经历和编年差异，违反同结果同奖励并扩大验证矩阵。
3. **独立战术人物和战役存档**：战术场景复制队员与结局，再在退出时同步回家族。它会造成身份冲突与重复提交风险，与 M07 的共用人物身份及存档要求相反。

**负责人建议：**采用路径 1。手动提供逐回合战术选择；自动依 GDD §8.3 使用能力、情报、准备、资源、难度和随机因素一次结算。两者读取同一份任务简报和人物状态，写入同一事务。奖励平等是已确认规则；任务是否一律开放两种操作及自动检定公式是待批准决定，不得作为已确认事实或实现前置。

## 核心流程

1. **管理与安排**：玩家查看家族人物、个人活动计划及可用任务。所有活动检查人员是否存活、是否受伤、位置、已有时间占用和任务资格。
2. **任务简报**：显示目标、参与者、花费与行动占用、成功/代价/失败风险、已知敌情及可能人物后果；玩家可返回调整队伍，或选亲自执行/自动委派。
3. **执行**：亲自模式进入当前战术任务；委派模式以相同人员和出发状态调用自动解算。二者均不提前改变奖励或后果，任务期间禁止对队员进行冲突安排。
4. **一次性结算**：将任务标识、结果、日期、参与者及实际变化送入一个应用层结算入口。入口校验并原子提交人物状态、资源/名望/关系变化、个人经历及唯一家族编年条目；无效或重复提交不得造成部分写入。
5. **恢复家族循环**：结果回到管理 UI，显示前后值及个人/家族影响。人物可继续合法活动，月份按现有顺序结算；任务完成或资源不足等 GDD 暂停条件按既有规则暂停自动推进。
6. **保存与继承**：只允许在稳定管理/任务结果节点保存；加载恢复人员、任务完成状态、经历、编年、资源和结算幂等性。家主更替不转移个人经历，家族编年保持在同一条家史中。

## 规则与数据边界

- 人物身份与当前角色统一由现有家族/人物数据拥有；任务记录只引用稳定人物 ID。
- 任务活动占用需复用现有 `DailyActionState` / 任务执行状态；不得新增并行的玩家可见时间预算。
- 自动解算提议按任务启动时冻结的队伍、能力、情报、准备、资源、难度与一个可保存/重现的随机流输入。读档后不可再次结算已提交任务。
- 所有任务共用 GDD §8.3 的五种结果，使用同一套结果数据和结算处理：

| 结果 | 目标状态 | 可能的共同后果 |
| --- | --- | --- |
| 完全成功 | 主要目标完成 | 完成奖励；任务定义的名望、信用、隐蔽度和世界关系变化；按任务定义产生经历。 |
| 成功但有代价 | 主要目标完成 | 完成奖励加明确代价；可能造成队员受伤或资源损失。 |
| 部分成功 | 仅部分目标完成 | 仅发放已完成目标对应奖励；记录未完成目标及对应关系/政治变化。 |
| 失败并安全撤离 | 目标未完成，队员撤出 | 不发完成奖励；按任务定义结算花费、关系变化与可恢复伤势，不可直接死亡。 |
| 严重失败 | 目标未完成且行动崩溃 | 任务定义可造成伤势或死亡；死者必须在简报中说明可能性，不能由未告知的随机事件直接杀死关键继承人。 |

  同一任务结果记录包括确切受影响人物和效果；相同任务、相同结果记录必须写入相同奖励、人物后果、经历和编年内容。若检定结果不同，则由任务结局本身解释差异，不能按操作模式调整结算。
- **负责人提出的伤病/死亡规则，待用户批准：**人物状态为存活且无伤、存活且受伤、死亡。受伤者在任务后一个完整月度结算前不能参与体力/潜入任务，但可进行不冲突的管理活动；月度结算后伤势自动恢复，不改变基础能力。死亡是永久状态，保留 ID、亲属关系、经历和编年，退出所有任命/行动并从继承候选中移除；当前家主死亡交由现有继承/危机流程接管。只有严重失败可触发死亡，且该队伍成员可能死亡须在简报中明确。任务的每名队员后果来自该任务结果数据，而非手动/自动模式。
- **名望、信用和世界关系：**按 GDD 分离家族名望与隐蔽度；雇主信用按雇主 ID 保存；不把名望当成隐蔽度的反向值。每个任务结果明确列出它影响的雇主/势力和数值前后值；不允许“世界变化”成为未定义的泛化字段。
- 结果事务记录每名队员伤病/死亡前后值、每类资源和名望/隐蔽度/信用/势力关系的实际增减、人物经历条目及唯一家族编年。UI 对发生的变化展示 before/after。
- 上述伤病时长、严重失败死亡限制及结果映射是负责人方案，须经用户审阅后才能转为实现规则；任务资源值和关系增减由具体任务配置并在简报显示。
- 失败、撤退和结果提交失败是不同状态。提交失败应保留可重试或可恢复的原状态，不能写入部分资源、人物或历史变化。
- 存档模式迁移遵循现有 `SaveDataMigrator` 与 `SaveDataValidator`；若新增字段则提升 schema 并覆盖当前受支持旧版本，原始存档无效时不得覆盖。

## 验收体验

- 在同一场战役中安排个人行动并执行一项可手动/可委派任务；玩家能够看到任务占用与冲突理由。
- 手动完成至少一个成功结局；从干净存档再次自动完成同任务结局，断言该结果下资源奖励、人物后果、个人经历与家族编年一致。自动模式本身不授予专属奖励。
- 分别覆盖完全成功、成功但有代价、部分成功、失败并安全撤离、严重失败五种结果，确认简报、统一结算、实际代价与重复提交保护；未选择任务定义的结局不得被静默合并。
- 将一名队员的任务结果写回原家族人物；检查人物身份、伤病/存活状态、个人经历、家族编年及世界变化。
- 在终局管理界面保存、退出并读档；完成至少一次家主交接后，确认任务结果与人物经历仍归属于原参与者、家族历史未重复。
- 用户可以解释手动与自动差异、简报中的风险和每项结果变化；若差异看似是模式奖励或任务强制要求手动，验收失败。

## 失败与风险

- **当前 M06 面板及场景接入尚未完成验证。** M07 的场景实现须等 M06 代码复审、场景 Validator 和 Play Mode 通过后再开始；不能基于未验证的 UI/结果契约继续叠加。
- **当前人物生命模型较轻。** 如果无可复用伤势/死亡状态，需谨慎扩展人物模型、存档校验与迁移；不要只在 UI 加状态。
- **奖励平衡不明。** 当前只锁定同一结局的手动/自动奖励相同；不同结局的具体奖励与风险值留给任务数据和试玩，不在本设计中假定。
- **长流程幂等性。** 任务、人物经历、家族编年与资源必须共同防止读档/重复按钮造成双重结算。
- **历史验收待办。** M02–M05 的最终用户里程碑验收仍需保留独立状态；M07 技术通过不自动把它们标成用户接受。

## 实现计划前仍需锁定

以下影响玩家可见规则，须在实现计划前由用户批准或修改：

- 是否所有任务都必须允许自动委派，还是允许个别任务仅手动/仅自动；负责人建议所有任务均提供两种方式、不设强制手动。
- 是否批准按 GDD §8.3 的六类输入（能力、情报、准备、资源、难度、随机因素）自动结算，并在简报展示主要风险；具体权重可在实现计划中按现有检定约束给出。
- 是否批准表中五种共用结果及每种结果的目标/后果边界；任务逐项奖励和关系数值随后列入任务内容配置。
- 是否批准伤病持续一个完整月度结算、暂停参与体力/潜入任务、月结自动恢复；严重失败才允许死亡，且简报必须告知该队伍成员面临的死亡可能。
- 家族名望与隐蔽度分开保存、雇主信用按雇主保存、势力关系用明确实体 ID 表达；负责人建议只接入当前已存在的势力/雇主模型，不添加新的世界仿真层。
- M06 固定单任务如何扩展成足以演示“管理—个人活动—任务—月结—继承”的最小连续场景；实施计划需给出与既有系统的映射及存档迁移列表。

这些细节不得改变用户确认的等结局奖励原则；超出上述范围的玩法扩张需另行审阅。
