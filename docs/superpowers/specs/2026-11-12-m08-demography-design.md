# M08A 家族人口动态设计

**状态：**已获用户批准（2026-11-12），M08A 实现已完成。2026-11-13 lead Play Mode 到达两次年界并观察到自然死亡、自主婚姻、以及 Save/Load 后日期与编年史行保留；该次运行未核验完整存档契约。生成配偶 ID/性别/生年、未完成怀孕与 RNG 的读档恢复、家主死亡继承、出生衔接及死后家谱标签仍未在 Play Mode 核验。用户最终里程碑验收仍待办。本文是自然死亡与 NPC 自主婚姻的设计权威，只记录已批准规则，不新增机制。

## 意图

GDD v4.0 要求家主随时间衰老、退休或死亡，并在 §14.2 统计长期家族灭亡、人口与平均年龄。当前人物已有出生年份和生死状态，但只有 M07 任务严重失败能造成死亡；固定 SC-022 演示之外没有自主婚姻。M04B 已提供确定性怀孕与出生，因此跨代长期结果缺少配偶和自然人口流失。

本切片让实际游戏月结产生可保存、可追溯的死亡和婚姻事实；后续 M08 模拟器运行同一 `GameSession` 规则，而不复制一套人口模型。

## 目标

- 每年对家族在世人物结算一次年龄相关的自然死亡概率。
- NPC 成年单身人物可通过确定性婚姻结算获得正式配偶；新配偶成为有稳定 ID 的家族成员。
- 死亡、配偶关系、人口子状态、编年史和可读档数据一起提交或一起回滚。
- 继承人死亡或家主自然死亡接入既有继承流程；孕育者死亡取消其未完成的怀孕。
- 婚姻和死亡进入现有家族界面及编年史投影，不需要新增 UI 页面。

## 非目标

- 不加入疾病、战争、寿命上限、人口容量、自动收养或离家系统。
- 不自动替玩家控制的当前家主择偶。
- 不改变玩家正式婚姻允许多位配偶的既定规则；自动 NPC 行为每人仅在没有在世配偶时尝试婚姻。
- 本切片不实现长期模拟器或物价系统；用户已批准的真实价格指数/通胀规则与 §14.2 模拟器作为独立 M08B 继续设计和实现。

## 约束与现有实现

- GDD v4.0 为设计权威；旧 M1–M7 文档仅作历史记录。
- `SuccessionPersonLife` 已保存 `BirthYear / Alive / Retired`，`AgeAt` 按年份计算；`PersonState` 已有 Male/Female/Unspecified 性别。
- 月结在 `GameSession.TryAdvanceToNextMonth` 中已快照日期、随机流、继承世界和编年史，并已有 M04B 出生事务。
- 使用持久化的 `RandomStreamKind.WorldSimulation`，并按稳定 `PersonId` 顺序取随机数。
- 当前婚姻命令受 SC-022 演示锁定；通用结算必须复用现有合法关系、存档、家族名册和编年史规则。
- 不加 Unity 包，不改 `Library` / `Temp`，保留所有 `.meta` 与 GUID；不覆盖混合 WIP。

## 考虑过的做法

1. **在现有月结事务中加入纯规则规划与原子应用（推荐）**：游戏和后续模拟器共用同一套规则；现有快照可保护存档与随机流。会扩展月结和人口状态的测试。
2. **在 UI 或月份结束后单独修改人物**：接线较少，但死亡可能与出生、继承、编年史部分提交，不采用。
3. **只在模拟器里虚构死亡和婚姻**：统计结果不能代表实际游戏，不采用。

采用方案 1。死亡、出生和婚姻都由月结事务规划并在其克隆状态中应用；任一写入失败时恢复日期、家族、关系、随机流及编年史。

## 规则提案

### 年龄与自然死亡

- 因 `AgeAt` 只按年份计算，自然死亡每年在十二月到一月的月结边界触发一次；年龄使用新日期计算。
- 每次结算开始时截取在世家族成员，再按 `PersonId` 序排序；这一名单内每人只消耗一次 `WorldSimulation` 随机检定。新生儿不在本次名单中。
- 基础年度死亡概率：0–14 岁 `0.5%`，15–39 岁 `0.5%`，40–59 岁 `1%`，60–69 岁 `4%`，70–79 岁 `12%`，80 岁及以上 `25%`。概率只用于初版调参，不宣称历史统计准确。M08B 的粮荒扩展每连续短缺 3 个月增加 `50‰`，最多增加 `250‰`；因此最高有效年死亡率为 `50%`（80 岁及以上且达到最大加成）。
- 自然死亡把既有 `Alive` 设为 false，保留人物、家谱和关系历史；清理可行动作和产业任命，并追加一条事实编年史。
- 自然死亡使执行中的 M05 护送委托失去可执行执行人时，月结在同一事务内按既有 `Abandoned` 规则关闭该委托（保留预付、不结算、不发报酬、不留运行 ID，并写入一条行动编年史），使同一日期状态可立即保存与读档。
- 年界委托判定顺序固定为：自然死亡在 1 月 1 日年界生效。若执行人属于本次 `naturalDeaths`，且月结模拟到 `nextDate`（1 月 1 日）时委托仍为 `InProgress`，则死亡优先——在推进/结算该日之前先按 `Abandoned` 关闭，绝不产生任务结果、名望、任务历史或 `Missions` 随机抽取。12 月 31 日已处于终态的委托保持不变，不再改写。该关闭若意外返回失败，月结事务整体失败，不得提交无法保存的进行中行。
- 当前家主死亡调用既有 `SuccessionService.BeginDeathSuccession`。如果产生待处理继承决策，本月跳过 NPC 婚姻结算。
- M04B 的本月到期分娩先于本次死亡结算；死亡者未到期的怀孕在同一事务中取消。死亡检定和出生顺序需由 EditMode 测试锁定。

### NPC 自主婚姻与配偶生成

- 仅在十二月到一月边界尝试；候选名单取月结开始时在世的家族成员，按稳定 ID 排序。
- 当前家主由玩家控制，不自动择偶。其他候选人须达到 `Succession.AdulthoodAge`、具有 Male/Female 性别且没有在世正式配偶。性别未知者不推断。
- 每名合格候选人每年进行一次 `15%` 自主婚姻检定。已有配偶者本轮不参与；丧偶者可在后续年度再次尝试。新生成配偶当年不再参与第二次配对。
- 候选资格取自月结开始时的名册快照：同一月结中因自然死亡而丧偶的人，本轮仍按“有在世配偶”排除，不会在同一结算立刻再婚；其再婚检定从下一年度边界开始。
- 新配偶为相反性别的成年人，年龄尽量与候选人相差不超过 5 岁；配偶年龄不受生育年龄限制。若二人不满足 M04B 生育年龄条件，则照常登记婚姻但不会产生怀孕。
- 新人物使用稳定且可重放的 ID、原创名字、确定的基础属性及既有人员初始化路径；加入家族名册、生命周期、发展状态、每日行动和正式配偶关系。
- 自动行为只为没有在世配偶的人登记一位配偶；玩家手动多配偶能力继续沿用 SC-022 已批准规则。
- 婚姻追加一条家庭婚姻编年史。新配偶从下一个月开始参与 M04B 怀孕检定。

## 持久化与失败保护

- 预期复用当前人员性别/生年/生死、成员、亲属、成长、行动和编年史存档字段；若实现必须新增字段，应先在计划中明确 schema 迁移和旧档默认值。
- Save/Load 往返必须保留自然死亡状态、自动生成配偶的稳定 ID/性别/生年、正式婚姻、未完成怀孕及随机流。
- 死亡和婚姻的编年史追加失败时，月结不得留下半个关系、失踪成员、重复随机消耗或推进后的日期。

## 验收证据

- EditMode：每个年龄段概率边界、只有年度边界检定、同种子同结果、稳定候选排序、未知性别排除、玩家家主排除、丧偶再婚、配偶不重复、怀孕下一月才可开始、家主死亡进入继承、孕育者死亡取消未完成怀孕。
- EditMode：年界委托边界三种情形——执行人本次死亡且委托在 1 月 1 日仍进行中时先按 `Abandoned` 关闭（无任务结果/报酬/名望/任务历史/`Missions` 抽取，且同日存档可校验并往返）；12 月 31 日已完成结算的委托保持终态不被死亡改写；死亡名单只有非执行人时，同一到期委托仍照常结算并写入任务历史，不产生 `Abandoned` 行。
- EditMode：失败注入后时钟、继承世界、关系、人员子状态、随机流、怀孕与编年史完全回滚；保存再读档后仍一致。
- Unity：使用当前已打开 Editor 的 Test Runner 和 Pipeline；分别记录编译、EditMode、Console、场景验证和 Play Mode。短期 Play Mode 核验一次死亡继承、一次 NPC 婚姻和出生衔接；不得把自动测试当真人试玩。
- M08 §14.2 的 100 年、1000 种子模拟及真实通胀指标是后续 M08B 验收，不由本切片宣称完成。

## 留给实现者的选择

- 仅当不改变以上规则时，可选择具体纯函数/结果类型名称和现有 UI 的呈现位置。
- 若当前 `GameSession` 不能在不加载图形场景的情况下稳定建立默认新局，应先做最小 Editor 测试确认，并在代码实现前反馈架构阻碍；不允许创建近似模拟规则。
