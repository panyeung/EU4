## 结论

- **正常 SC-013 / SC-010 开局不会进入调试会话**。带堆栈的临时日志实测：普通开局全程 `DebugModePanel.Open()` 与 `GameSession.BeginDebugSession()` 零次调用；读回 `IsDebugSessionActive=False`、无调试面板、调试根 `activeSelf=False`。
- **本轮复现到的调用路径**：标题页 `M09DebugModeEntry` 的 `onClick` → `TitleScreenController.OnDebugModeButton` → `StartDebugSession` → `DebugModePanel.Open` → `BeginDebugSession`。该入口是普通 UnityEvent；标题隐藏时按钮 `activeSelf=False`，真实指针点不到，但脚本可直接 `onClick.Invoke()`（不校验 active），从而在普通战役中打开调试会话并让玩家槽被拒。
- **归因边界**：本轮没有历史事故发生当时的触发栈或操作记录。普通 SC-013/SC-010 开局实测零调用，因此不能据此断定隐藏入口就是那次事故的原始触发；历史原始触发仍不确定。本卡修复的是这条已证实可复现、可被门禁阻止的脚本直调路径。
- **修复点**：`TitleScreenController.StartDebugSession()` 增加门禁——标题页不可见且当前无调试会话时拒绝进入（状态行「Debug 入口只在标题页可用，当前未进入调试会话。」）。标题页可见进入、已激活会话后重开窗口、`IsDebugSessionActive` 存档门禁均保持不变。
